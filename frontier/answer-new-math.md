I would put the clock on **strict score records**. On this clock, a tick is not “the sieve tried another integer.” It is “the sieve produced a pair that survived strictly more testing than every earlier pair.” There is a total, bounded algorithm for one tick. Its termination proof can even use a pair whose two members are *provably composite*. This gives a way to tell exactly what made the proof work, and what it did not prove.

There are two output interfaces for this machine:

| Request | What must be returned before the recursive call | Status |
|---|---|---|
| `nextRecord` | A fresh strict record, with the result of its twin test | Provably productive |
| `nextTwin` | A fresh strict record **passing** its twin test | Productivity not established |

The first interface gives a nontrivial step-level non-stagnation theorem. It is not a proposed new meaning of “another twin was certified.”

## (a) Logic: finite search inside a guarded producer

Use an inductive type of finite numerals, generated by `zero` and `succ`. Operationally a numeral is a finite construction; the rule for a variable of numeral type allows the construction to be supplied later. No operation takes a completed set of all numerals as input. A prime certificate is likewise finite: for the ordinary CPNF process it is the record of a least-survivor step. This is a potential-infinity *reading* of inductive types, not a prohibition on giving the logic a classical model.

Use the following two judgments, both ordinary dependent types:

- `s : S ⊢ tick(s) : Σ t : S, E(s,t)` — a **terminating** computation of a successor and evidence of the specified event.
- `s : S ⊢ run(s) : Run(E,s)` — an indefinitely observable producer, specified coinductively by the constructor
  \[
  \frac{e:E(s,t)\qquad r:\mathrm{Run}(E,t)}
       {\mathrm{emit}(e,r):\mathrm{Run}(E,s)} .
  \]

The productive recursion rule is
\[
  \mathrm{run}(s)=
    \mathsf{let}\ (t,e)=\mathrm{tick}(s)\
    \mathsf{in}\ \mathrm{emit}(e,\mathrm{run}(t)).
\]
The recursive call is guarded by `emit`. **Loop identity** means the continuation has the same indexed protocol `Run(E,–)` with the *same* event relation \(E\); it does not mean equality of the old and new states. **Non-stagnation for \(E\)** means exhibiting such a producer from the initial state. If \(E\) permits stuttering, this proves little. The point of the design is to put an independently testable, strict progress condition in \(E\).

## (b) The twin process and its two clocks

I use the **positive-row score readout in the Lean sources**. This specifies the observation being implemented: it is not a claim that record ticks are iterations of the paper’s completion `while` loop.

A pair at \(n\ge1\) **survives** a finite blocker list \(B\) if division of both \(6n-1\) and \(6n+1\) by each entry gives a nonzero remainder. A survival certificate can be the table of these remainders, checked by recomputation. Write \(s(n)=\texttt{score}\ n\). Use the established interpretation of \(s\) and the established test \(s(n)=6n-1\); neither is a new axiom.

Here is the exact **microstep**. The state \((a,h)\) means that rows through \(a\) have been read and \(h\) is their maximum score, with empty maximum zero. Start at \((0,0)\). Compute \(b=a+1,\ v=s(b)\).

1. If \(v\le h\), go to \((b,h)\) without emitting.
2. If \(v>h\), go to \((b,v)\) and emit \((b,v,\mathsf{test})\), where `test` is the Boolean \(v=6b-1\).

Thus no twin is lost in suppressing a non-record microstep, by your `isRecord_of_twin`. A false test is a verdict, not an inconclusive search.

The **record tick** batches microsteps up to and including the first emission. Its event relation from \((a,h)\) to \((b,v)\) requires
\[
 a<b,\qquad v=s(b)>h,\qquad
 \forall i\in[a+1,b-1]\;\;s(i)\le h .
\tag{R}
\]
The label is computed from \(b,v\), not chosen by the producer. Relation (R) preserves the running-maximum invariant. The **twin tick** instead batches through the first emission with true label. Guarded recursion is available for either clock; it supplies a producer only *after* one can implement the corresponding terminating tick.

On this presentation, a permanent covering after row \(a\) would provide a proper divisor \(d\ge2\) of at least one member at each \(n>a\). No intentional adversary is needed; for finite rows a least-factor computation checks the obstruction. The logic does not exclude this pattern of verdicts. It excludes a *fixed finite blocker list* as a universal explanation, by arithmetic, not by a fairness rule. In particular, determinism gives no permission to discard an infinite suffix of false labels in finite time.

## (c) Checker

No new kernel is needed. For example, this is the entire guarded rule as a file `Clock.v` for Coq 8.19 (`coqc Clock.v`):

```coq
Section Clock.
  Context {S : Type} (E : S -> S -> Type).

  CoInductive Run (s : S) : Type :=
  | emit : forall t : S, E s t -> Run t -> Run s.

  Variable tick : forall s : S, {t : S & E s t}.

  CoFixpoint run (s : S) : Run s :=
    match tick s with
    | existT _ t e => emit s t e (run t)
    end.
End Clock.
```

`tick` here is a parameter of a generic theorem, **not** a postulate that either arithmetic tick exists.

For the existing **Lean** project I would avoid porting the correspondence proofs. Use a state transformer returning a dependent pair and implement observation of the run by structural recursion on a finite request count: zero returns the empty trace; successor calls `tick` once and observes its continuation with the predecessor count. This implements the same finite observations without requiring a coinductive kernel extension. Keep the executable score from `Correspondence.lean`; do not implement the tick by calling the `noncomputable` stage functions. The bound below turns the missing computation into `List.find?` on a `List.range` of known length. The proof that `none` is impossible is the arithmetic part, not a productivity annotation.

## (d) First theorem: record productivity with a composite deadline

Write \(\operatorname{DoubleComposite}(n)\) when **each** of \(6n-1,6n+1\) has an exhibited proper divisor greater than one. For any finite cursor \(a\) and threshold \(h\), set
\[
 M=(a+1)(h+1)!,\qquad x=6M,\qquad D=36M^3 .
\]
The theorem is
\[
\boxed{\begin{aligned}
  &s(D)>h\ \land\ \operatorname{DoubleComposite}(D),\\
  &\mathrm{tick}_R(a,h):
    \sum_{b:\mathrm{Numeral}}
       (a<b\le D)\ \times\ (s(b)>h)\
       \times\!\!\prod_{a<i<b}(s(i)\le h).
\end{aligned}}
\]
Here the bounded product is a finite table of checks. No running-maximum hypothesis is required for the theorem; that invariant is needed only to interpret its outputs as global records.

**One-line proof idea:** \(6D=x^3\), so \(x^3\pm1\) evade every divisor from \(2\) through \(h\), yet factor by \(x\pm1\); scan to this guaranteed threshold crossing and return the first one.

In detail, \(M\ge a+1\), so \(D>a\). Each \(2\le d\le h\) divides \(M\), hence divides \(x^3\) and neither neighbor. Both least prime factors therefore exceed \(h\). But
\[
 x^3-1=(x-1)(x^2+x+1),\qquad
 x^3+1=(x+1)(x^2-x+1).
\]
Since \(x\ge6\), these are proper factorizations. Scanning rows \(a+1,\ldots,D\) must succeed at or before \(D\); the failed comparisons before the first success give precisely the table in (R). In an implementation, use \(D-a\) as recursion fuel, **not** as a list that must be materialized before the scan begins. The deadline is a termination certificate, not an efficiency estimate.

For a Lean development the dependency order is short: prove `h < score D` by contradiction using `Nat.minFac_dvd`, `Nat.minFac_prime`, and `Nat.dvd_factorial`; prove the two factor identities over the integers or after eliminating truncated subtraction; implement the fuelled first-crossing scan; use the deadline lemma to eliminate its exhaustion branch. The guarded producer then needs no arithmetic reasoning. For example, after row \(1\) the threshold is \(5\); the next tick actually stops at row \(2\), whose score is \(11\), without going anywhere near its deadline.

**What is new here is the contract, not a classical independence result.** The machine must answer every request with a *strict improvement in sieve endurance*, and there is a finite certificate of its ability to answer that does not rely even accidentally on its deadline being a twin. Classical mathematics can prove the same theorem. If “non-stagnation” is required to mean fresh **successful twin certifications**, replacing that contract by (R) would only relabel a weaker result. The honest benefit of the loop vocabulary is that the difference becomes executable: changing the client from “return the next record” to “discard false labels and keep going” invalidates the termination proof at one precise line.
